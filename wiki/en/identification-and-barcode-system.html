Identification and barcode system

Version 0.1 · Chapter 9 of 14 · Updated 18 Nov 2026

Several fields described in the Data dictionary, such as the project acronym, the collector center, the patient and sample codes and the omics type, do more than describe the data: they combine to form the barcode, the unique identifier of each patient, sample and assay. Users do not type the barcode; the platform generates it automatically from these fields.

ATPBR uses a standardized identification system to ensure the traceability of participants, biological samples, experiments and generated data throughout the entire life cycle of a project or study. This system is based on structured barcodes, which work as unique and persistent identifiers within the platform.

Inspired by the The Cancer Genome Atlas (TCGA) barcode, the ATPBR identification system was adapted to meet the specific needs of Brazilian cancer research, incorporating requirements for governance, de-identification, multi-omics integration and biobank management.

The barcode is the main mechanism linking the biological material stored in the National Tumor Bank (BNT), the metadata recorded on the platform and the files generated during the analytical processes. In this way, the same identifier follows the sample from its collection to the production of molecular results and their release for research.

Principles of the Identification System#

The ATPBR barcode system was developed on the basis of four fundamental principles:

Unique Identification

Each participant, sample and assay receives a unique combination of codes, eliminating ambiguity and allowing the unequivocal identification of the objects recorded on the platform.

Traceability

All data produced in ATPBR can be linked to their biological and experimental origin. The system makes it possible to reconstruct the complete history of a sample, from its collection, storage and processing to the generation of the associated omics files.

De-identification

The identifiers contain no personal information or data that would allow the direct identification of participants, and the correspondence between the codes and the individuals is kept only at the institution of origin. Because the barcode deliberately links all records of the same participant, the data are pseudonymized, not anonymous: for this reason, they remain protected as sensitive personal data (see Data governance).

Interoperability

The barcode structure was designed to facilitate integration between the different ATPBR modules and to promote compatibility with standards widely used in biomedical data repositories and platforms.

Biological Material and Digital Objects#

The same barcode is used to connect different components of the ATPBR infrastructure.

In the physical environment, it identifies materials stored in the National Tumor Bank, including tissue, blood, plasma and other biological samples.

In the digital environment, the identifier is used to associate:

  • Clinical metadata.
  • Experimental information.
  • FASTQ files.
  • Processed files.
  • Analytical results.
  • Processing and provenance records.

This strategy ensures consistency between the different layers of the platform and makes it possible to trace the origin of any data available in ATPBR.

Barcode Structure#

The ATPBR identifier is not a single code: it is built incrementally and in a nested way, following the hierarchy of the Data model (Patient → Sample → Assay). Each level fully reuses the barcode of the previous level and adds its own fields.

Level What is identified Composition Example
Patient the study participant PROJECT-CANCER-CENTER-PARTICIPANT ATPBR-56-001-1234
Sample the collected biological material ‹patient barcode›-SAMPLE-TYPE ATPBR-56-001-1234-5678-01AB
Assay the omics experiment performed on the sample ‹sample barcode›-ASSAY ATPBR-56-001-1234-5678-01AB-G0101

For this reason, the "complete" seven-field barcode exists only at the assay level: it is the result of stacking the three levels. Read from left to right, separated by hyphens (-), the complete structure is:

PROJECT-CANCER-CENTER-PARTICIPANT-SAMPLE-TYPE-ASSAY

Example:

ATPBR-56-001-1234-5678-01AB-G0101

Each component of the identifier is described in the following sections.

Interpreting the Barcode#

Each segment of the ATPBR barcode has a specific meaning and represents a piece of information associated with the project, participant, sample or experimental assay.

Taking the example:

ATPBR-56-001-1234-5678-01AB-G0101

The interpretation is as follows:

Field Value Meaning
Project ATPBR Brazilian Population Tumor Atlas
Cancer (ICD-10) 56 Malignant neoplasm of ovary (C56)
Participating Center 001 Brazilian National Cancer Institute (INCA)
Participant 1234 Participant code
Sample 5678 Biological sample identifier
Sample Type 01AB Frozen malignant tumor tissue
Assay G0101 Whole genome sequencing (WGS), run 01, lane 01

Therefore, the barcode above identifies a sample of frozen malignant tumor tissue from a patient with ovarian cancer, collected at INCA in the context of the ATPBR project and submitted to a whole genome sequencing assay.

Meaning of the Codes#

  • Project Code

This is the project acronym, defined by the user when registering the Project. It must have 5 to 7 uppercase letters and is unique on the platform: each project has its own.

Example:

Code Project
ATPBR Brazilian Population Tumor Atlas
  • Cancer Code (ICD-10)

Identifies the participant's cancer diagnosis by the category of the International Classification of Diseases (ICD-10, CID-10 in Portuguese), represented by the 2 digits of the code, without the letter "C". For example, category C56 (malignant neoplasm of ovary) enters the barcode as 56.

How this code is defined: the user does not type the code. In the Patient registration, the user provides the cancer type (OncoTree classification, among the types of the tissue defined in the Study), the subtype, when known, and the organ of origin of the tumor. From these answers, the platform automatically calculates the corresponding ICD-10 category, and that value is what enters the barcode. For hematologic neoplasms (leukemias, lymphomas, myeloma), the category is defined by the subtype, regardless of the organ.

Examples of codes:

Code ICD-10 category Description
15 C15 Esophagus
16 C16 Stomach
18 C18 Colon
20 C20 Rectum
34 C34 Bronchus and lung
43 C43 Melanoma
44 C44 Other neoplasms of skin
50 C50 Breast
53 C53 Cervix uteri
56 C56 Ovary
61 C61 Prostate
91 C91 Lymphoid leukemia
92 C92 Myeloid leukemia
99 (not applicable) Non-malignant neoplasm (benign, in situ or of uncertain behavior)

The ICD-10 malignant neoplasm categories (C00 to C97) are accepted, plus code 99 for non-malignant neoplasms. The complete list is available in the metadata spreadsheet. The codes are stable: codes already in use are never changed.

  • Participating Center Code

Identifies the collector center, the institution responsible for collecting or submitting the sample. Each center receives a 3-digit code.

How a center enters the system:

  1. The institution is registered by the user when creating the Project, together with its ROR identifier.
  2. From then on, it appears in the "Collector Center" controlled vocabulary and becomes available for selection when registering a patient.
  3. The code recorded in the barcode is that of the institution selected in this vocabulary.

The codes are global and permanent:

  • Each institution has a single fixed code across the entire platform, uniquely identified by its ROR id, so that the same real center always resolves to the same code.
  • A new code is generated only when the institution has not been selected on the platform before; centers already in use reuse the existing code.
  • Codes are never reused or removed, so that the barcodes of samples already registered remain valid.

Predefined centers:

Code Institution ROR id
001 Brazilian National Cancer Institute (INCA) 055n68305
002 Cancer Institute of the State of São Paulo (ICESP) 005vqqr19
003 Ceará Cancer Institute (ICC) 01pg9bv14

New centers receive the next available sequential code, in the order in which they are first used.

  • Participant Code

A 4-digit code that identifies the participant. It is defined by the collector center and entered in the patient_id field of the patient registration.

Example:

Code Meaning
1234 Participant code

The code must have no relation whatsoever to the participant's personal data: for example, do not use the medical record number or parts of the date of birth.

  • Sample Code

A 4-digit code that identifies the biological sample linked to a participant. It is also defined by the collector center and entered in the sample_id field of the sample registration.

Example:

Code Meaning
5678 Specific biological sample

The same participant may have multiple samples. The platform does not accept two records with the same barcode and warns you when it detects a possible duplicate registration.

  • Sample Type Code

The Sample Type field is made up of four characters and describes, at the same time, the biological material, the pathological status and the preservation method of the sample.

Structure:

TTSP

Where:

  • TT = Material type (2 digits)
  • S = Sample status (1 letter)
  • P = Sample preservation (1 letter)

For example, 01AB corresponds to:

  • 01 = Tissue
  • A = Malignant Tumor
  • B = Frozen

Result: Frozen malignant tumor tissue.

The combination of these codes makes it possible to describe, in a compact and standardized way, the main biological and operational characteristics of each sample, while maintaining traceability throughout the entire ATPBR workflow.

  • Assay Code

The Assay field identifies the omics modality used and information associated with the experimental run. This field makes it possible to distinguish different experiments performed on the same sample and to maintain the traceability of the generated data.

Structure:

OCCLL

Where:

  • O = Omics modality (1 character)
  • CC = Experimental run number (2 digits)
  • LL = Lane number (2 digits)

For example:

G0101

corresponds to:

  • G = Whole Genome Sequencing (WGS)
  • 01 = First run
  • 01 = Lane 1

Result:

Whole Genome Sequencing (WGS), run 01, lane 01

Omics Modality Codes#

Code Omics Modality
G Whole Genome Sequencing (WGS)
X Whole Exome Sequencing (WES)
R RNA-Seq
P Gene Panel Sequencing

Codes M (DNA methylation) and B (5-base DNA methylation) are reserved for future versions (see the accepted modalities in Data types).

Run Number#

A sequential number assigned automatically by the platform. The user does not set this number manually.

The run is identified by the combination of three fields entered in each Experiment: sequencing date, sequencing center and sequencing platform. Numbering is done within each Study:

  • The first combination recorded in the Study receives 01, the second receives 02, and so on.
  • Experiments with the same date, the same center and the same platform belong to the same run and receive the same number.
  • Once assigned, the run number does not change.

For this reason, these three fields are required and must be filled in carefully. Besides distinguishing technical replicates and new runs of the same experiment, this identification makes later batch-effect analyses easier, where it is important to know which data were generated in different runs.

Code Meaning
01 First run
02 Second run
03 Third run
... Subsequent runs

Lane Number#

Represents the sequencing lane used during the run.

Code Meaning
01 Lane 1
02 Lane 2
03 Lane 3
04 Lane 4
... Other lanes

Identifying the lane supports technical traceability and the investigation of possible sequencing-related problems.

Interpretation Examples#

Code Interpretation
G0101 WGS, run 01, lane 01
X0102 WES, run 01, lane 02
R0201 RNA-Seq, run 02, lane 01
P0101 Gene panel, run 01, lane 01

Examples of Complete Barcodes#

Barcode Interpretation
ATPBR-56-001-1234-5678-01AB-G0101 Frozen malignant tumor tissue sample from ovarian cancer submitted to WGS in run 01, lane 01
ATPBR-50-002-3456-7890-01AC-R0101 FFPE-preserved malignant tumor tissue sample from breast cancer submitted to RNA-Seq in run 01, lane 01
ATPBR-61-003-4321-8765-02KB-X0201 Frozen normal non-tumoral blood sample from prostate cancer submitted to WES in run 02, lane 01

The combination of the assay code with the other barcode fields makes it possible to uniquely identify the biological and experimental context associated with the data produced in ATPBR, ensuring traceability from the physical sample to the files generated by sequencing.
